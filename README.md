## 📖 项目简介

**QianDao V2** 是一个基于 **Python 3.11+ & FastAPI** 开发的自动化签到管理工具。旨在帮助用户轻松管理各类每日签到、定时 HTTP 请求、自动打卡等任务。系统支持一键解析导入 `curl` 命令，具备精确到秒的定时调度能力，并针对整点抢签场景提供了专属的 **抢零点优化模式**。

项目采用无数据库的 JSON 文件持久化设计，极其轻量，支持 Docker 一键部署。

---

## ✨ 核心特性

- 🚀 **Curl 智能解析**：直接粘贴浏览器导出的 `curl` 命令，一键自动提取 URL、请求方法、请求头 (Headers) 与请求体 (Body)。
- ⏱️ **秒级精细调度**：支持全局定时与单任务独占定时，粒度精准至 `时:分:秒`。
- ⚡ **抢零点优化模式 (Aggressive Mode)**：针对零点/整点抢签场景，提供微秒级时间切片对齐、连接池复用与高频补发机制。
- 🔍 **结果断言与重试**：支持自定义“成功关键字”与“失败关键字”匹配断言，支持 0-5 次失败自动重试与 1-120 秒超时控制。
- 🔔 **多渠道通知推送**：内置 Telegram Bot 与 Custom Webhook 通知，支持成功/失败差异化推送策略。
- 🔒 **访问安全与文档控制**：内置 Session 登录鉴权防护；遵循 FastAPI 安全规范，默认关闭 API 自动文档暴露，支持环境变量动态开启。
- 💾 **零依赖持久化**：采用纯 JSON 文件 (`data/state.json`) 存储，备份与迁移极为简单。

## 🛠️ 快速开始

### 方式一：Docker Compose 部署（推荐）

1. 启动服务：
   ```bash
   docker-compose up --build -d
   ```

2. 访问控制台：
   打开浏览器访问 `http://localhost:8080`，输入默认密码 `admin123456` 登录。

### 方式二：本地运行

#### 使用 `uv` (推荐)

```bash
uv run python -m app.main
```

#### 使用原生 `python`

```bash
pip install -r requirements.txt
python -m app.main
```

打开浏览器访问 `http://localhost:8080` 即可。

## ⚙️ 环境变量与系统配置

可以通过修改环境变量来定制系统运行参数：

| 环境变量 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `TZ` | `Asia/Shanghai` | 容器与系统时区设置 |
| `APP_TIMEZONE` | `Asia/Shanghai` | 应用时间计算时区 |
| `QIANGDAO_DEFAULT_PASSWORD` | `admin123456` | 首次初始化时的默认登录密码 |
| `ENABLE_DOCS` | `false` | 是否开启 FastAPI 调试自动文档 (`/docs`, `/redoc`) |

> 🔒 **安全提示**：为保证生产环境安全，FastAPI 自动文档 (`/docs`, `/redoc`, `/openapi.json`) 默认关闭。如需调试接口，可在启动时指定环境变量 `ENABLE_DOCS=true`。

## 🔥 抢零点模式说明

针对热门服务/站点需要抢 `00:00:00` 首签的需求，可在任务编辑页面勾选开启 **“抢零点模式”**。

### 优化机制：
- **微秒级时间切片对齐**：调度器按微秒级轮询对齐目标秒数。
- **连接池预热与复用**：请求使用 HTTP/1.1 与 HTTP/2 共享连接池，减少建连延时。
- **微秒级补发保障**：到达设定秒数后立即触发，并在极短窗口内进行快速补发尝试。
- **真实耗时与发起时间刻度**：历史记录中精确显示请求发起的系统时间戳，方便评估是网络延时、调度延迟还是站点响应慢。

> 💡 **建议**：抢零点模式会消耗略多的 CPU 时间与连接资源，建议仅针对需要竞争首签的重点任务开启。

---

## ⏰ 定时与时区策略

- **优先级规则**：若任务开启了“单任务定时”，系统将优先使用该任务自设的时间，忽略全局定时配置。
- **秒级兼容**：定时时间均支持 `HH:MM:SS`，旧版升级会自动补充 `:00` 秒。
- **时区对齐**：默认锁定 `Asia/Shanghai` 时区，彻底避免 VPS/容器因 `UTC` 时间导致的“设置 00:00 实际 08:00 执行”等时差错位问题。

## 📂 数据与迁移

系统所有数据（任务配置、调度规则、通知密钥、密码 Hash 及历史执行日志）均统一保存在：

```
data/state.json
```

- **数据备份**：只需备份 `data/state.json` 文件即可完成全部数据的备份。
- **平滑迁移**：在新环境中挂载该文件启动 Docker 容器或本地服务，即可即时无缝恢复所有配置与历史记录。
